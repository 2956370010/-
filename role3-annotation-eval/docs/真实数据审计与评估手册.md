# 真实数据审计与评估手册

本手册说明公开数据落地后，如何把它接进工程包，并依次完成角色三的自动标注审计、模型对比和分割面积评估。所有命令默认在 `role3-annotation-eval` 目录下用项目自带 Python 执行。

## 0. 准备与目录约定

运行前先确认两处：

- 公开数据在 `../public_data/images/` 与 `../public_data/labels/`，标签为 YOLO 格式（0=fire、1=smoke）；
- `data/` 里如果还留着合成样例，用第 1 步的 `--reset` 清掉，避免旧标签混入真实指标。

## 1. 构建独立测试集

测试集必须与训练集隔离。先从公开数据切出测试集，并把目录初始化好：

```powershell
$py = 'C:\Users\saini\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $py scripts/build_test_set.py --public-data ..\public_data --out-data data --count 200 --reset
```

这一步会：

- 把图片复制到 `data/images/`；
- 把公开标签复制到 `data/gt/`（仅作初始参考，最终金标准要人工校正）；
- 生成 `data/images.json`（宽高索引）和 `data/test_set.csv`（含 fire/smoke/negative 标记）；
- 初始化 `annotator_a / annotator_b / auto / preds_yolo / preds_open / masks_gt / masks_pred` 目录。

角色一训练 YOLO 时，要把 `data/images/` 下的这些图排除在训练集之外。

## 2. 自动预标注

在训练机装好 `transformers`、`torch` 与 GroundingDINO/SAM 权重后运行：

```powershell
& $py scripts/preannotate.py --image-dir data/images --config config/pipeline.json
```

输出 `data/auto/`（YOLO 标签）和 `data/masks_pred/`（SAM 掩码），运行配置快照在 `output/preannotation/run_record.json`。提示词、阈值、模型版本等都在 `config/pipeline.json` 里，先按需改好再跑。

## 3. 200 幅双人独立标注

角色一和角色二各自对 `data/images/` 的同一批测试图独立标注，不要看对方的标签：

- 角色一结果写入 `data/annotator_a/`；
- 角色二结果写入 `data/annotator_b/`；
- 文件名与图片同名，例如 `img_0001.txt`，每行 `class_id cx cy w h`（归一化）；
- 无目标的图写空文件。

标注工具可用 labelImg、Ultralytics 标注流程或 Roboflow 导出。角色三不参与这 200 幅标注，只负责统计。

## 4. 标注审计

```powershell
& $py scripts/audit_200.py
```

输出在 `output/audit/`：

- `audit_metrics.json`：自动标注 vs 标注者 A、vs 标注者 B、以及 A vs B 的 P/R/F1/mIoU；
- `per_class.csv`：fire/smoke 分列统计；
- `per_image.csv`：逐图框数；
- `audit_summary.md`：总体指标与工时节省估算。

## 5. YOLO 与开放域模型同集对比

让角色一在 `data/images/` 的同一测试集上跑两个模型，预测结果写成 YOLO 格式（`class_id cx cy w h conf`）：

- YOLO 预测放入 `data/preds_yolo/`；
- 开放域模型（GroundingDINO 等）预测放入 `data/preds_open/`。

把测速结果（FPS、硬件、batch、是否含后处理）填进 `config/pipeline.json` 的 `comparison.speed`，然后：

```powershell
& $py scripts/compare_models.py
```

输出 `output/compare/comparison_table.csv` 与 `comparison_metrics.json`。对比口径固定为同一测试集、IoU=0.5、输入分辨率 640x640。

## 6. 50 幅分割面积与误差分析

从测试集里挑 50 幅，准备两个掩码目录（PNG 或 `.npy`，0/1 二值）：

- `data/masks_gt/`：金标准掩码（人工勾画，或用 SAM 后人工修正）；
- `data/masks_pred/`：SAM 自动掩码（第 2 步已生成，也可重新生成）。

```powershell
& $py scripts/segment_area.py
```

输出 `output/segment/`：面积占比、掩码 IoU、面积误差、蔓延速率、失败案例，以及给角色二前端用的 `frontend_timeseries.csv/json`。

## 7. 生成报告图表

三步的指标 JSON 都生成后，统一出图：

```powershell
& $py scripts/make_charts.py
```

图表在 `output/charts/`：自动标注审计、模型对比、面积趋势、逐图面积误差。

## 8. 报告落盘

把 `output/` 里的指标和图替换进 `docs/角色3-报告章节.md` 的“待填写”位置，即可并入设计报告。

## 常见问题

- `audit_200.py` 报图像数不足：确认 `data/images.json` 已生成，且 `annotator_a/annotator_b/auto` 三个目录都覆盖同一批图片。
- `compare_models.py` 的 FPS 显示“待填写”：先填 `config/pipeline.json` 的 `comparison.speed`。
- 想跑通全流程但还没有真实模型/人工标注：用 `scripts/run_all_demo.py` 跑合成样例，验证链路本身。
